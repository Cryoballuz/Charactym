## 各阶段详细步骤

### 阶段 0：环境准备
1. `adb devices` 确认手机已连接，读取机型与 Android 版本。
2. 检查电脑上的 JDK、Android SDK、Gradle 环境，缺什么补什么。
3. 用官方 android-cli 工具创建项目骨架：应用名 Charactym，包名 `com.charactym.app`，代码放 `android/` 子目录。
4. 构建一个空白应用，安装到手机，能正常打开。
- **验收**：手机上能看到并打开 Charactym 空应用（截图确认）。
- **暂停点**：环境就绪 → 报告用户 → 等确认。

### 阶段 1：数据层
1. 建立 Room 数据库与 `glyphs` 表（见技术方案 §2）。
2. 实现图片存取工具：画布数据 ↔ PNG 文件（256×256 黑白）。
3. 写增、删、改、查、搜索的基本数据接口。
- **验收**：编译通过；用一段临时测试代码在手机应用内写入/读出 1 条记录并显示成功。
- **暂停点**：数据层就绪 → 报告用户 → 等确认。

### 阶段 2：画布与保存
1. 实现画布组件：缩放、拖动、辅助线开关、触点→格子换算。
2. 实现画笔、橡皮、撤销（50 步）、清空（带确认）、笔刷三档。
3. 实现映射字框（可选，单个字符）、备注框、保存按钮与校验提示（映射字与备注至少填一个）。
4. 保存后清空画布便于连续录入。
- **验收**：用户真机手写一个人造字 + 映射字 + 备注，保存成功；重启应用后数据仍在。
- **暂停点**：录入流程可用 → 请用户实机体验 → 等确认。

### 阶段 3：浏览与详情
1. 浏览列表：缩略图 + 映射字 + 备注摘要，按时间新→旧。
2. 详情页：大图 + 映射字 + 完整备注。
3. 编辑：预填原数据，保存即更新（可重画）。
4. 删除：确认后删除记录与图片。
- **验收**：用户能浏览、点开、编辑、删除已有文字。
- **暂停点**：请用户实机体验 → 等确认。

### 阶段 4：搜索
1. 搜索页：一个搜索框，同时模糊匹配映射字与备注。
2. 结果列表点击进详情；空结果显示提示。
- **验收**：按映射字搜出对应人造字；按备注关键词（如「太阳」）搜出相关记录。
- **暂停点**：请用户实机体验 → 等确认。

### 阶段 5：导出与备份
1. 导出 PNG 到「下载」文件夹（支持全部导出）。
2. 整体备份：生成 zip 备份文件到手机存储。
3. 恢复备份：选择备份文件后恢复全部数据与图片。
- **验收**：导出的 PNG 能在相册/文件管理器打开；备份后卸载重装应用，恢复备份后数据完整。
- **暂停点**：请用户实机验证 → 等确认。

### 阶段 6：收尾打磨
1. 按设计规范核对配色、文案、间距、提示。
2. 处理边角情况（空列表提示、连续快速点击、横竖屏等）。
3. 全流程真机复测一遍（录入→浏览→搜索→导出→备份）。
4. 更新 docs 与 devlogs，形成交付说明。
- **验收**：用户整体满意；交付使用说明。

## 变更流程

- 任何阶段中若发现需要调整需求/设计，先在本文件「变更记录」登记并与用户确认，再动手。

## 变更记录

- 2026-08-19：笔刷尺寸调整——画笔 小/中/大 = 4/8/12 像素，橡皮 = 10/20/30 像素（用户反馈，原为 1/2/3）

- 2026-08-19：修复编辑页串状态问题——启用 Navigation 3 每条目独立 ViewModelStore 装饰器（用户反馈）
- 2026-08-19：数据库升级策略：移除开发期 fallbackToDestructiveMigration，改为显式 Migration 登记表（防升级丢数据）
- 2026-08-19：映射字改为可选——允许任意单个 Unicode 码点字符（可非汉字），映射字与备注至少填一个；输入框文案改「映射字（可选）」「备注」；无映射字记录在列表中留空显示，导出文件名用 `<id>.png`
